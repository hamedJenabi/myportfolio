# To PRD

Create a practical PRD from the current context and repo state.

## Workflow

1. Identify the product surface, target audience, and desired outcome.
2. Summarize current state and constraints using concrete repo facts when available.
3. Define goals and non-goals before listing features.
4. Write user stories for the primary audience.
5. Convert the work into functional requirements, content requirements, design requirements, and technical requirements.
6. Add milestones with acceptance criteria that can be verified.
7. Call out risks, assumptions, and open decisions.
8. Keep placeholders explicit and easy to replace.

## Output Shape

Use this structure unless the user requests another format:

- Title
- Summary
- Background / Current State
- Target Users
- Goals
- Non-Goals
- User Stories
- Requirements
- Milestones
- Acceptance Criteria
- Risks & Mitigations
- Open Decisions
- Future Enhancements

Write in clear product language. Avoid vague work items like "improve UX" unless paired with measurable acceptance criteria.
